# U4 bricks: new brick types, soul sandstone, mud, midori and duskbound building blocks

Reference: Quark 4.1-488 (`release-4.1-488+1.21.1`), `content/building/module/{MoreBrickTypes,SoulSandstone,
MoreMudBlocks,Midori,DuskboundBlocks}Module.java`, `content/building/block/MudBrickLatticeBlock.java`, the
generated recipes / loot tables / tags under `src/generated/resources/data/` and `assets/quark/lang/en_us.json`.
Behaviour only; textures are original (`tools/textures/bricks.ps1`).

## 1. Modules covered

### MoreBrickTypes
Nine brick blocks, each with stairs, slab, vertical slab and wall: Blue Nether Bricks, Sandstone Bricks, Red
Sandstone Bricks, Soul Sandstone Bricks, Cobblestone Bricks, Mossy Cobblestone Bricks, Blackstone Bricks,
Dirt Bricks, Netherrack Bricks. Each copies the properties of its parent block (hardness, resistance, sound,
map colour) and requires the correct tool for drops. Options turn groups off (`enableBlueNetherBricks`,
`enableSandstoneBricks`, `enableCobblestoneBricks`, `enableBlackstoneBricks`, `enableDirtBricks`,
`enableNetherrackBricks`); blackstone, dirt and netherrack bricks also need cobblestone bricks (their recipe
uses them); soul sandstone bricks also need the SoulSandstone module.

### SoulSandstone
Soul Sandstone (stairs, slab, vertical slab, wall), Chiseled Soul Sandstone, Cut Soul Sandstone (slab,
vertical slab), Smooth Soul Sandstone (stairs, slab, vertical slab). Brown, strength 0.8, requires a pickaxe.
The whole family (and soul sandstone bricks) is in `soul_fire_base_blocks` (fire on it is soul fire) and
`soul_speed_blocks` (Soul Speed boots work on it).

### MoreMudBlocks
Carved Mud Bricks, Mud Pillar (axis pillar) and Mud Brick Lattice (a see-through cutout cube that can be
waterlogged), all copying mud bricks.

### Midori
Moss Paste (an ingredient, smelted from a moss block, 50% compost chance), the Midori Block (4 moss paste,
"green purpur") with stairs, slab and vertical slab, and the Midori Pillar.

### DuskboundBlocks
Duskbound Block (purpur + dusky myalite, or obsidian when SpiralSpires is off) with stairs, slab and vertical
slab, and the Duskbound Lantern (light 15). Copies purpur. All are `dragon_immune`.

## 3. Mechanics

- **Content gate** (`src/feature/bricks/Bricks.cpp`). The pack always defines every block; the config decides
  what is obtainable, as Quark's `setCondition` and recipe flags do:
  - recipe loading is hooked (`Recipes::_loadRecipe`, installed at mod load, so it runs for the BDS world
    and every client world): a recipe of this unit loads only when its result is enabled, plus Quark's own
    extra flags: `soul_sandstone_wall` (crafting) and `soul_sandstone_stairs` (stonecutter) also need
    `sandstone_bricks` (Quark 4.1-488's data); `duskbound_block` needs SpiralSpires (`worldbeyond.json`
    `enableSpiralSpires`) and the item `lepton:dusky_myalite`, `duskbound_block_without_myalite` the opposite.
  - creative entries of disabled items are not added (`CreativeItemInitializer::_addCreativeItemServer` /
    `_addLooseCreativeItem`).
  - vertical slabs also follow U1's VerticalSlabs module (`vslabs.json` `enableVerticalSlabs`, true when the
    file is absent), as Quark only registers them with that module.
  - group rules: blue nether = MoreBrickTypes && enableBlueNetherBricks; (red) sandstone bricks =
    MoreBrickTypes && enableSandstoneBricks; soul sandstone bricks = that && SoulSandstone; (mossy)
    cobblestone bricks = MoreBrickTypes && enableCobblestoneBricks; blackstone / dirt / netherrack = cobblestone
    bricks && their option; the other modules by their enable key.
  - The log line `bricks: <n> recipes and <m> creative entries disabled by config` follows each world load.
- **requiresCorrectToolForDrops**: `Block::playerDestroy` is skipped for `lepton:requires_tool` blocks when the
  held item lacks the tool tag: no drops, as Java skips `playerDestroy` when the player cannot harvest.
- **Soul fire** (`FireBlock::_trySpawnSoulFire`, `SoulFireBlock::canSurvive`): fire placed above a
  `lepton:soul_fire_base` block turns into soul fire and survives there (SoulSandstone enabled).
- **Soul Speed** (`Mob::normalTick`): a mob with Soul Speed boots (level L) on the ground above a
  `lepton:soul_speed` block gets a movement speed modifier `+0.03 * (1 + 0.35 L)` (Java's
  `getSoulSpeedBonus`, additive); while it moves, the boots take 1 damage with a 4% chance per tick. The modifier
  is removed as soon as the mob leaves the block or the boots.
- **Infiniburn**: netherrack brick block types get Bedrock's `InfiniBurn` block property on every world load,
  so fire on them never burns out (as on netherrack).
- **Dragon immunity** (`EnderDragon::_checkWalls`): duskbound blocks in the dragon's box are swapped for bedrock
  (vanilla-immune) while the game checks the box and restored right after (no updates, no drops); the dragon
  counts as blocked, as in Java.
- **Lattice**: alpha-tested cube, no light dampening (skylight passes like glass), `minecraft:liquid_detection`
  lets it hold water (waterlogging).
- **Moss paste** composts with a 50% chance (`minecraft:compostable` 50).
- **Pillars** (mud, midori): placed along the clicked axis (`lepton:pillar`).

## 5. Config

`config/bricks.json`:

| Key | Type | Default | Meaning |
|---|---|---|---|
| `version` | int | 1 | (Lepton) |
| `enableMoreBrickTypes` | bool | true | MoreBrickTypes module |
| `enableBlueNetherBricks` | bool | true | This also comes with a utility recipe for Red Nether Bricks |
| `enableSandstoneBricks` | bool | true | This also includes Red Sandstone Bricks and Soul Sandstone Bricks |
| `enableCobblestoneBricks` | bool | true | This also includes Mossy Cobblestone Bricks |
| `enableBlackstoneBricks` | bool | true | Requires Cobblestone Bricks to be enabled |
| `enableDirtBricks` | bool | true | Requires Cobblestone Bricks to be enabled |
| `enableNetherrackBricks` | bool | true | Requires Cobblestone Bricks to be enabled |
| `enableSoulSandstone` | bool | true | SoulSandstone module |
| `enableMoreMudBlocks` | bool | true | MoreMudBlocks module |
| `enableMidori` | bool | true | Midori module |
| `enableDuskboundBlocks` | bool | true | DuskboundBlocks module |

Changes take effect at the next world load (recipes and the creative inventory are built then), like Quark,
whose content modules need a restart. The tag behaviours (soul fire, soul speed, dragon) follow `/quark reload`
immediately.

## 7. Bedrock differences / not ported

- "Utility recipe for Red Nether Bricks" (`enableBlueNetherBricks` description): Quark 4.1-488 ships no such
  recipe (the description is left over from older versions), so there is none here either.
- `polished_blackstone_brick_vertical_slab` (Quark gates it with the blackstone bricks flag) is a vanilla
  material's vertical slab and belongs to U1.
- Creative tab order: Quark inserts the blocks after specific vanilla blocks (coal block, sea lantern, mud brick
  stairs, ...). Bedrock custom blocks only choose a category and group, so they appear at the end of the
  construction tab / in the stairs, slab and wall groups.
- Smelting experience (moss paste 1.0, smooth soul sandstone 0.1): Bedrock furnace recipes have no experience
  field; the furnace gives Bedrock's default.
- A disabled block placed earlier stays in the world (Quark would show a missing block); `/give` still works.
- Infiniburn relies on Bedrock's `InfiniBurn` block property; the soul speed modifier is Lepton's own (Bedrock's
  native soul speed only checks soul sand / soil).
- Fences/walls collision height: see tools/pack/README.md (generator limitation).
